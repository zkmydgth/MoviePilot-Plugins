## 配置备份（ConfigBackup）

定时备份 MoviePilot 系统配置、数据库及插件配置到指定目录，支持按份数与天数双重保留、自动清理、手动触发和一键还原；备份内容可勾选，并可上传到 WebDAV 远端保存与取回。

| 项目 | 说明 |
| --- | --- |
| 标签 | 系统工具, 备份 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/configbackup` |
| 数据库要求 | 无（PostgreSQL 10+ / SQLite 均可；其它类型跳过数据库部分） |

### 功能特性

- **定时自动备份**：按 cron 规则定期备份；也可在配置页开「立即运行一次」，保存后在后台执行、不阻塞保存
- **备份内容可勾选**（默认全选 = 全量；取消勾选即只备份所选部分；**一项都不选会拒绝备份，不打空包**）：
  - **数据库**：PostgreSQL 完整逻辑导出（表结构、数据、索引与序列），兼容 10+ 含 18.x，无需外部 `pg_dump`；SQLite 以 `user.db` 文件方式备份，**备份前自动执行 WAL checkpoint 落盘**，避免复制到不完整快照
  - **系统配置**：`app.env`、`category.yaml`
  - **站点 Cookie**：`/config/cookies`
  - **插件配置**：`/config/plugins`
  - **附加路径**：自定义路径（按清单回原路径还原），支持 `路径|*.log,node_modules,cache` 排除规则
- **双重保留策略**：保留份数 + 保留天数**满足其一即保留**；新旧按文件名时间戳判定，不依赖文件拷贝时间（避免把最新备份当成最旧的删掉）
- **备份包自检**：打包后校验完整性，损坏的包自动隔离为 `.broken`，不占保留名额、不会被当成可还原备份
- **备份清单**：包内写入清单，列表直接显示每份备份的「内容」（数据库 / 系统配置 / 站点 Cookie / 插件配置 / 附加路径），选哪一份还原心里有数
- **两阶段确认还原**：选中备份 → 页面确认后执行，支持中途取消
- **备份目录灵活配置**：支持下拉候选 + 自由输入
- **通知**：备份与还原的**成功和失败都会推送**；通知场景可在配置页选择（具体发到微信还是 Telegram，由宿主的「通知设置」按该场景决定）
- **WebDAV 远端备份**（可选）：备份包**自检通过后**上传到 WebDAV；详情页可直接查看远端备份并**下载**或**下载并还原**（下载到本地后走与本地一致的两阶段确认与安全网，不做直接远端还原）；远端按「保留份数 + 保留天数」同一套规则清理旧包，且**只清理本插件生成的备份包**；详情页提供「测试 WebDAV 连接」（只读探测，不在远端留文件）
  - 上传失败会让**整次备份标红**，但**本地包仍生成且可用**，消息里会写明「本地备份已生成 xxx.zip（可用）；上传失败：原因」
  - 远端保留份数留空则跟随「保留备份个数」；超时时间可配（`user.db` 可能几百 MB，建议 ≥300 秒）

### 使用说明

1. 在配置页设置**备份目录**、**保留份数**与**保留天数**（该天数内的备份一律不删，填 0 表示只看份数），配置 cron 定时规则
2. 需要立即备份时，点页面上的**手动备份**按钮
3. 还原时在列表选中目标备份（先看「内容」列确认这份包含什么）→ 点【还原】→ 页面确认后执行
4. 附加备份路径每行一个；目录可写 `路径|*.log,node_modules,cache` 排除不需要的内容
5. 需要用网盘异地留存时，打开**上传到 WebDAV**，填写 WebDAV 地址（含目录）、账号与密码、远端目录；保存后到**插件详情页**点「测试 WebDAV 连接」确认连通，再点「手动备份」验证一次上传
6. 从远端恢复：在详情页「远端备份」表里点**下载并还原** → 包会先下载到本地并校验 → 再到本地列表点【确认还原】执行

> ⚠️ **还原为覆盖式**：备份包中含有的配置会回到备份那一刻，**备份之后新增的插件配置与站点 Cookie 将被清除**（站点需重新登录）；备份包里没有的部分不受影响。
> 还原前会自动先备份当前状态作安全网，**安全网失败即中止还原**，不会在没兜住的情况下动任何配置。
>
> 数据库：PostgreSQL 以 SQL 方式导出还原（插件直连主库，无需外部工具）；SQLite 以数据库文件方式备份还原。若使用其它数据库类型（如 MySQL），将跳过数据库部分，仅备份配置与插件数据。
>
> 取消勾选「数据库」不会再顺带备份 SQLite 的 `user.db` —— 数据库文件归属「数据库」项，与「系统配置」分开。
>
> ⚠️ **WebDAV 远端备份默认不加密**：备份包含站点 Cookie 与数据库，上传到网盘即明文存放，请确认该 WebDAV 服务端可信；密码建议使用网盘的**应用专用密码**，不要用登录密码。
> 「测试 WebDAV 连接」按钮在**插件详情页**（配置表单里没有按钮组件）。

## 保种空间守护（SeedSpaceGuard）

存储空间不足时，自动清理保种目录中「保种最久」的资源（种子 + 文件），避免触发 H&R。

| 项目 | 说明 |
| --- | --- |
| 标签 | 存储管理 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/seedspaceguard` |

### 功能特性

- **空间阈值触发**：定期检查卷剩余空间，低于设定阈值时自动开始清理
- **多目录清理**：「保种/清理目录」为多行文本框，**每行填写一个绝对路径**，支持 `#` 注释行，自动去重并剔除互为嵌套的目录
- **两种清理模式**：
  - **种子级（seed）**：删除「**清理目录内**」保种最久的种子（监控目录之外的种子不会被删，未过保护期的也不删），并按**严格顺序**连带收尾——删种前先建 inode 索引（删种后下载侧文件消失即无法再枚举）→ 删主种子 → 删媒体库侧同 inode 硬链接 → 摘除同内容辅种 → 清理转移记录与空目录。一步到位不留红种，且空间真实释放。索引与清理均带**归属判定**：若该种子的内容目录与其它种子共用（实测存在「一个目录下多集各一个种子」的布局），会先把这类目录从索引范围中剔除，只删除**有证据属于本种子**的 inode，同目录其它种子的文件（含其媒体库侧副本）**绝不误删**
  - **仅文件（file）**：仅删除文件，**由本插件自行处理硬链接**，无需依赖外部插件
- **硬链接自动双侧删除（两种模式均支持）**：按 `(st_dev, st_ino)` 自动识别文件身份，同一 inode 在多目录下的所有副本一次性删净，避免「删一侧留一侧、空间一点没释放」的假删除。清理前先做**归属判定**——只删「本种子自身文件清单」或「本次索引范围内」的 inode，被判定为同目录其它资源的路径一律跳过并计数告警（不静默放过）；若完全取不到归属依据，则**整体放弃本次硬链接清理并告警**，宁可媒体库侧残留也不误删
- **辅种连带清理（种子级，可关闭）**：判定键为「内容路径 + 种子名」**两者都相同**，据此区分真辅种与合集多集——实测 29 组真辅种（单组最多 19 条）会被连带删除，121 组合集多集（同目录但种子名不同）**绝不误删**。辅种**默认同样受保护期约束**：同一个文件在别的站点可能刚辅上，那边一样可能有 H&R 要求；确认没有这层顾虑时，可在「辅种也受保护期约束」开关里显式关闭
- **无主文件清扫（种子级，可选）**：种子连同文件都被移出监控目录后，留在媒体库的硬链接会失去所有入口。开启后按 inode 归组判定，**整组都不被任何种子引用**才删除；只要组内有一条路径仍被引用即整组保留。适用于两个网络位置或媒体库/下载目录混放的场景
- **目标下载器可限定（种子级）**：下拉多选，自动读取 MoviePilot 已启用下载器，不选 = 全部
- **空壳种子自动回收**：每轮清理前先扫一遍「文件已全部删除、种子却仍留在下载器里做种」的空壳并回收，**不删除任何文件**。判定按**该种子自身**的文件清单复核，因此同一目录下多个种子各自独立判定——某个种子的文件删完了就会被回收，**不受同目录其它种子的文件影响**；反过来，自己的文件还在就绝不回收。默认只扫「内容路径在监控目录内」的种子；若种子做过保存目录变更或做种转移，其内容路径可能已不在监控范围内——开启下方开关可一并覆盖
- **部分删除的种子也能正常处理**：曾被手动删过部分文件的种子，仍能按剩余文件正常清理，且依靠 inode 复核防止误删「被重建的同名新文件」
- **删到达标为止（按缺口预选）**：按保种时间从早到晚清理，直到剩余空间恢复至阈值以上；删除后轮询等待空间实际释放再复核
- **空间未释放即停（宁可少删）**：删除后按字节精度核对实际释放量，若空间确实没有释放（可能存在快照引用或目录外硬链接），**立即停止本轮清理并告警**
- **保护机制**：
  - 最近 N 天添加的种子/文件不清理（保护期）
  - 支持按后缀保护指定文件（如 `*.part`、`*.!qb` 等未完成文件）；**该项留空 = 不保护任何文件**（空值不再回落默认模板）；配置页提供「恢复默认保护后缀」按钮，点击先弹确认框、再把默认模板填回输入框（**仍需点「保存」才生效**）
  - 自动跳过 DSM 系统目录（`@eaDir` 等）与回收站
- **DSM 索引残片自动清理**：清除 `@eaDir` 中对应真实文件已不存在的索引残片（双重白名单校验，不会误删用户数据）
- **空壳目录巡检（默认开启）**：每轮在空间判断**之前**扫一遍监控目录，删除「除 `@eaDir` 等 DSM 索引残片外已无任何内容」的空壳目录——常见成因是下载器删种时删掉了文件，但群晖索引残片让目录无法 `rmdir`，而旧逻辑只在插件自己删完文件后顺带收尾，这类「文件不是插件删的」残留没有触发点。**只删目录与可安全识别的索引残片**：目录内只要还有任一真实文件、符号链接或无法识别的元数据就整棵保留；配置目录本身永不删除；试运行只列不删
- **联动清理（可选，默认全关）**：
  - **联动删除种子**（**两种模式通用**）：「仅文件」模式下有严格前置条件——必须**该种子自己的**文件都已删除，才会删除该种子。判定按种子自身文件清单复核，同一目录下的其它种子不受影响，也不会因它们的存在而挡住本种子的删种；若种子不在主候选集内（未完成 / 内容路径不在监控目录内），会改用「放宽候选集」再取一次以完成物理复核，仍取不到时保留种子并在结果中列出「未做物理复核」的数量，便于人工核对；「种子级」模式下它同时是**空壳回收的总闸**（关闭后，文件已删完但仍残留的空壳种子不会被回收）
  - **删除转移记录**（**两种模式通用**）：先按目标路径匹配，未命中再按源路径匹配
- **通知**：清理结果站内消息推送；定时触发沿用「无动作即静默」，**手动与命令触发一律推送结果**。摘要会写明本次处理数量；中途因空间未按预期释放而停手、或任务被取消时，摘要里会直接标注，不会仍显示「处理完成」

### 使用说明

> 🧭 **配置项已按清理模式分组**，选定「清理模式」后只会看到该模式相关的设置：
>
> | 分组 | 显示条件 | 包含项 |
> | --- | --- | --- |
> | **全局基础设置** | 常驻 | 手动触发、启用插件、清理模式、清理目录、空间检查路径、阈值、保护期、cron、等待秒数、试运行、通知 |
> | **种子级模式设置** | 仅「种子级」 | 目标下载器、连带清理硬链接与辅种、辅种也受保护期约束、清理无主文件 |
> | **仅文件模式设置** | 仅「仅文件」 | 保护文件后缀 |
> | **种子联动设置（两种模式通用）** | 常驻 | 联动删除种子、删除转移记录、空壳回收覆盖监控目录外 |
>
> 分组标题与条件显示由前端 `props.show` 实现；若前端版本较旧不支持，会退化为
> **全部展开显示**（功能不受影响，仅需自行按标题辨认归属）。
>
> 📌 **每项设置下方的说明文字默认常驻显示**，无需点开/关闭开关即可阅读（插件已为
> 全部带说明的控件补上 `persistent-hint`，桌面端与移动端表现一致）。

1. 在配置页填写**保种/清理目录**（每行一个绝对路径）、**空间阈值**与**保护期天数**
2. 选择**清理模式**（种子级 / 仅文件）
3. 按需开启种子级增强开关（见下方说明），**建议先保持默认、观察一轮后再逐项开启**
4. 先点**试运行**预览「将删哪些、预计释放多少空间」，确认无误后再正式清理
5. 配置 cron 定时规则，或使用命令 `/seedguard` 手动触发

#### 种子级增强开关

> 下表前四项仅在**种子级**模式显示；「空壳回收覆盖监控目录外」属**两种模式通用**，
> 故列在此处仅为归类便利，实际对仅文件模式同样生效。

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 连带清理硬链接与辅种 | **开** | 删种时一并清理媒体库侧硬链接与同内容辅种。关闭则退回旧行为（只让下载器删文件，媒体库侧硬链接残留、空间不释放会被误判为「删了没释放」而停手告警） |
| 辅种也受保护期约束 | **开** | 只在「连带清理」开启时才有意义。开启后处于保护期内的辅种不会被连带摘除；关闭则表示「只要主种子够老，同内容的所有辅种一并摘除」 |
| 清理无主文件（无种子引用） | **关** | 清扫不再被任何种子引用的孤儿硬链接。默认关是刻意的：它会主动删除用户文件、判定链较长，**建议先配合试运行观察一轮**，确认判定结果符合预期后再开启实跑 |
| 空壳回收覆盖监控目录外的种子（**两模式通用**） | **关** | 空壳回收默认只扫监控目录内的种子，而空壳越彻底（目录已消失）越容易被范围过滤挡掉。开启后把范围外的已完成种子一并纳入判定——**只回收已无任何文件的空壳，只摘种子、不删除任何文件**。依赖「联动删除种子」总闸，总闸不开则不生效 |

> 💡 **同一目录下多个种子互不干扰。** 一部剧的若干集各自成种、共用一个文件夹时，插件的空壳判定与联动删种都按**种子自身**的文件清单进行：某个种子的文件删完即回收该种子，同目录其它种子的文件**原封不动**；文件夹里还有其它文件时也不会被删除，直到确认清空才清理该文件夹。

> 💡 **清理范围是「除保护后缀外全部删除」**：配置目录下所有文件均纳入清理候选，不区分文件类型。「保护文件后缀」是**唯一**的保留手段，需要保留的文件务必填入该项（例如正在下载的 `*.part`）。**该项留空即不保护任何文件**——连正在下载的 `*.part` 也会被清理；误清空可点输入框下方的「恢复默认保护后缀」按钮（带确认弹窗）一键填回默认模板。

> ⚠️ **把种子和文件移出监控范围时，留意留在原目录的硬链接。** 这些残留需要开启「清理无主文件」才能兜住；该开关默认关闭。

## Telegram 自动签到（TgSignin）

多个 Telegram 账号按 cron 定时到各自订阅的 bot 签到（各类 Emby bot、签到 bot 等；bot 私聊与**群内签到**都支持），适合"每天手动点一遍很烦"的场景。

| 项目 | 说明 |
| --- | --- |
| 标签 | 工具 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/tgsignin` |

### 功能特性

- **多账号多 bot**：账号与签到目标都是逐行开关的槽位表单，账号与签到方式用下拉选择；每个 bot 单独配置签到方式与等待秒数
- **两种签到方式**：按钮式（先发 `/start` 拉菜单，再点文字含「签到」的按钮）、命令式（直接发命令，如 `/checkin`）
- **群内签到**：目标可以是**群**——公开群填 `@群用户名`，私有群填数字 ID（`-100…`，先用详情页「查询群组」查到）；群内一般用**命令式**，命令写 bot 在群里要的形式（如 `/checkin@example_bot`）
- **回复归属标识**（群签到可选，**只在该行是群目标时显示**）：填了之后只有回复里出现它才算本目标的本次结果，用于同一个群里多人同时签到、或群里另有闲聊时区分归属（填自己的站点账号名等）；留空时群里只排除真人发言。结果只认**目标自己发的**回复，别人同时签到不会串档
- **查群号**：详情页每个账号一个只读「查询群组」按钮，另有「更新群组（全部账号）」一次刷新全部账号的缓存（列表**不会自动更新**），也可用命令 `/tggroups` 把列表发到聊天里；配置页每个目标槽有「从已查到的群组选」组合框（**可输入群名关键词筛选**，**候选只列该行账号的群组**）+「填入本槽」按钮，点选后**自动解析出群号**写进该行，再按「保存」生效
- **两阶段登录**：账号槽里选「发送验证码」保存 → 填码后选「确认登录」保存，全程在插件内完成，兼容两步验证；session 存在 `/config/plugins/TgSignin/sessions/`，不随容器重建丢失
- **定时签到**：执行周期用 MP 的 cron 选择器（点开可选每天/每周/每月与时间，也可手输），默认每天 09:00
- **通知可配**：不通知 / 仅失败时 / 仅成功时 / 成功与失败都通知（默认仅失败时），通知正文含时间、来源与逐条摘要
- **结果可见**：详情页表格展示每个 bot 最近一次结果（时间 / 账号 / bot / 成功失败 / 回复摘要）
- **命令**：`/tgsignin`（立即签到，可带账号与 bot 参数）、`/tglogin`（聊天内完成登录）、`/tgstatus`（查看状态）、`/tggroups`（查群号，只读列出该账号的群与数字 ID）
- **后台执行**：发送验证码 / 确认登录 / 立即签到立刻返回，前台不转圈
- **结果分档**：每条结果分为 `签到成功` / `今日已签到` / `未确认` / `失败`，并区分「bot 弹窗说已签到」「回复里说已签到」「只回菜单」三种重复签到情形；**成功 / 已签到 / 失败三类关键词都可在配置里扩展**（接新 bot 不必改代码）。失败类内置覆盖「暂不可用 / 服务不可用 / 服务异常 / 稍后重试 / 系统繁忙 …」——bot 回「签到服务暂不可用，请稍后重试。」这类明确失败文案会**判失败并进入失败重试**
- **可选 AI 复核**：开关「自动使用 AI 确认」**默认关闭**；开启后仅对「未确认」的结果调用 MoviePilot 内置智能助手判定成功/失败（判失败进失败重试，无法判定则保持未确认、不影响其它判定），需先在 MP 里配置好智能助手
- **并发签到**：「并发签到上限」默认 **1（串行，与旧版行为一致）**；设为 2-4 时，同一账号下**每个 bot 一路同时触发**，总耗时从「逐条等待」降到「一轮等待」（账号之间仍串行，避免同账号多连接风控；每路带错峰抖动，命中 Telegram FloodWait 会按提示退避并重试一次，不影响其它路）
- **AI 自动归纳关键词**：开关默认**关闭**；开启后由 AI 判定回复属于成功/已签到/失败，并把它**逐字摘取**的短语自动补进对应关键词栏（**只增不删**、写入前**查重** —— 已存在的词不会重复添加；每栏上限 40 条），新增记录可在详情页回看
- **只认「本次」的返回**：按钮与回复都做时间归属过滤（只认发送之后收到的消息）——bot 离线/回复超时时，上一次的旧菜单、旧的「签到成功」都不再顶账，**无任何返回一律判失败**，日志里保留原始回复与弹窗摘要
- **失败重试**：当天失败的目标按「失败重试间隔」自动重试（默认 6 小时，可设 0 关闭），重试窗口到**次日 0 点**自动重置；**整个账号一轮没跑成**（连接超时 / 未登录 / session 失效 / 连接异常）时，改为按该账号的**每个目标**各记一条失败并带上原因，因此这些目标同样进重试窗口（通知的失败明细里会列出它们），当天可自动补签

### 配置要点

| 项 | 格式 |
| --- | --- |
| 账号 | 槽位表单：显示名 + 手机号（标识自动生成 `acc1…acc4`） |
| 签到目标 | 槽位表单：账号（下拉）+ **bot 用户名 / 群** + 方式（下拉）+ 按钮文字/命令 + 等待秒数 + 回复归属标识（**仅群目标行显示**，可选） |
| 查群号 | 详情页「查询群组 · <账号>」逐个查、「更新群组（全部账号）」一次刷新全部（列表不会自动更新）；配置页每行一组「从已查到的群组选」+「填入本槽」：候选只列该行账号的群组、可输入群名筛选，点选后自动截出群号写进该行，**仍需按「保存」**生效（只在框里打了筛选词、没点选候选项时会提示） |
| 高级 | 「文本模式」开关：用多行文本批量配置（`标识 \| 显示名 \| 手机号`、`账号 \| 目标 \| 按钮或命令 \| 内容 [\| 等待秒数] [\| 回复归属标识]`），条目数不限；与槽位**自动同步**：槽位镜像进文本，文本的前 4 个账号 / 前 8 条目标回填槽位，超出槽位容量的条目只留在文本里 |
| 代理 | 模式：跟随 MoviePilot（默认）/ 自定义 / 直连 |
| 执行周期 | cron 选择器（点开可选），或手输五段式 |
| 通知方式 | 四档：不通知 / 仅失败时（默认）/ 仅成功时 / 成功与失败都通知 |
| 失败重试间隔 | 小时数，默认 **6**；**0 = 不重试**。当天失败后每隔这么久重试一次，次日 0 点重置窗口 |
| 并发签到上限 | **1（默认）= 串行**；**2-4** = 同一账号内「每个 bot 一路」并发。建议 3；账号之间仍串行 |
| AI 自动归纳关键词 | 开关，默认**关闭**；开启后用 AI 判定档位并自动补词（只增不删、查重）。需先在 MP 里配置好智能助手 |
| 签到成功关键词 | 回复/弹窗命中任一即判「签到成功」；多个用 `\|` 或逗号分隔，**留空用内置默认**（含 签到成功 / 签到完成 / 打卡成功 / 领取成功 等） |
| 已签到关键词 | 命中任一即判「今日已签到」；多个用 `\|` 或逗号分隔，留空用内置默认（含 已签到 / 已经签到 / 签到过了 / 已打卡 / 已领取 等） |
| 依赖 | `telethon`、`python-socks[asyncio]`（随插件安装） |

## 综艺正片守卫（VarietyGuard）

整理综艺整季包（或单片）时，按关键词**只保留正片、静默跳过非正片**（先导片 / 纯享 / 花絮 / 加更 / 预告 / 特辑 等）。解决的是"先导片与正片**共用同一集号**（都叫 E01）导致整理时互相顶替"的问题。

| 项目 | 说明 |
| --- | --- |
| 标签 | 工具 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/varietyguard` |

### 功能特性

- **只对综艺生效**：作用域默认「媒体类型 = 电视剧 且 分类含 综艺」；剧集、国漫、电影等一律原样放行，不受影响
- **静默跳过，不产生失败**：在**整理计划阶段**把命中的非正片从候选清单里剔除；全被剔除时借用宿主的「无候选」静默分支 —— **不写整理失败记录、不发失败通知、不进重试**（因此也不会触发「文件整理失败智能接管」）
- **不动源文件**：全程只读判定，不移动 / 删除 / 重命名任何源文件 → **做种不受影响**
- **正片白名单**：命中白名单（默认 `正片`）的文件优先保留，适配「正片花絮」这类混合命名
- **关键词可配（内置 61 项）**：中文 35 项（`先导 / 花絮 / 加更 / 纯享 / 预告 / 学院 / 互动 / 采访 / 幕后 / 会员版 / 抢先 / 衍生 / 见面会 / 发布会 / 巅峰 / 盛典 / 颁奖 / 群访 / 晋级 / 突围 / 直击 / 速看 / 特别篇 / 特辑 / 彩蛋 / 未播 / 独家 / 尝鲜篇 / 森林体验篇 / 超前 / 尊享版 / 陪看 / 直拍 / 探班 / 直播`）+ 英文/数字 26 项（`Dinner / Pure / Plus / Teaser / Preview / Behind / Making / Club / Rapid Case / E00 / EP00 / Battle / Round / Cut / Reaction / Prologue / Epilogue / Start / SP / Detective Club / Extra / EX / Live / Pilot / Fancam / Before`），每行一个、支持正则、忽略大小写
- **英文/数字关键词自动加词边界**：内置默认里的 ASCII 词会自动包成 `(?<![A-Za-z])词(?![A-Za-z])` —— 因此 `MAXPLUS`、`StartUp`、`Clubhouse` 这类「含词串」不会被误伤；多词短语允许 `. _ - ` 空格 作分隔（`Rapid Case` 也能命中 `Rapid.Case`）；`E00`/`EP00` 刻意**不加词边界**（站内命名变体较多；裸词也会把 `S01E0012` 这类串算作命中，属有意为之）。⚠️ 自己新增的英文词不会自动加边界，需要时照写 `(?<![A-Za-z])Word(?![A-Za-z])`
- **试运行**：默认开启，只把命中的非正片记进日志与统计、不实际过滤 —— 建议先观察一轮再关
- **词表同步（可选，v1.0.6）**：填了「同步到自定义过滤规则」的 rule_id（如 `RULE4`）后，插件在加载与保存配置时把自己的**生效词表整条镜像**写入该规则的「排除」项 —— 搜索侧（自定义过滤规则）与整理侧（本插件）两份词表自动保持一致，**新增与删减都同步、即时生效、不消耗模型额度**。留空即关闭；规则不存在、词表项数超出 10~200、含 `|`/换行或拼接正则不合法时，只记日志、绝不改动规则
- **恢复默认关键词（v1.0.7 起，v1.0.8 加确认）**：配置表单里有「恢复默认关键词」按钮，点击先弹确认框，确认后把内置默认词表填回「非正片关键词 / 正片白名单」两个输入框（**仍需点「保存」才落库**）；详情页的同名按钮改为**两阶段** —— 先点「恢复默认关键词」选中，再点「确认恢复」才会写回配置并立即生效（可点「取消」放弃，10 分钟未确认自动作废）。用于「误删默认词、又不想手抄 61 项」的场景
- **可观测**：详情页显示补丁状态、累计跳过数、按关键词分布与最近记录；命令 `/varietyguard_status`（查看统计）、`/varietyguard_reset`（重置统计）
- **失败即放行**：补丁失配、正则非法或任何内部异常都只记日志并返回宿主的原始计划，绝不阻断正常整理

### 使用说明

1. 安装后打开「启用插件」即可，**「试运行」默认开启**：先观察一轮日志/统计，确认"哪些文件会被跳过"符合预期（详情页与 `/varietyguard_status` 均可查看）
2. 确认无误后关闭「试运行」即真正生效；某个词误伤时，直接在关键词表里删除或改成更精确的正则。注意默认词表里有几个**偏宽的词**（`Start` / `Battle` / `Round` / `Cut` / `Club` / `SP` / `巅峰` / `盛典` / `颁奖`）：若某部综艺的**正片**文件名恰好含它们会被跳过 —— 靠命中白名单 `正片` 兜底，或把这些词删掉/改精确
3. 作用域两项留空表示不限类型 / 分类；「匹配完整路径」默认关闭 —— 开启后整季包**目录名**含关键词会连正片一起跳过，谨慎使用

### 配置要点

| 项 | 说明 |
| --- | --- |
| 启用插件 | 总开关 |
| 试运行 | 默认**开**；只记录不过滤 |
| 跳过时发送通知 | 默认关；开启后每次真正跳过会发一条汇总通知（试运行不发） |
| 非正片关键词 | 每行一个、**正则**、忽略大小写；命中即跳过。内置默认 61 项（中文原样、英文词带词边界，**`E00` / `EP00` 例外不加边界**）；自行新增的英文词不会自动加边界 |
| 恢复默认关键词 | 按钮（v1.0.7 起，v1.0.8 加确认）：配置表单里点击先弹确认框、确认后填回两个输入框（再点「保存」生效）；详情页为两阶段「恢复默认关键词」→「确认恢复 / 取消」，确认后才写回并立即生效，10 分钟未确认自动作废 |
| 同步到自定义过滤规则 | 填自定义过滤规则的 ID（如 `RULE4`）即开启：插件在**加载与保存配置**时把生效词表**整条镜像**写入该规则的「排除」项，新增与删减都同步、即时生效、不消耗模型额度。**留空=关闭**。安全闸：规则不存在、词表项数超出 10~200、或拼接后的正则不合法时只记日志、不改动规则 |
| 正片白名单 | 优先级高于关键词；命中即保留 |
| 生效媒体类型 | 默认 `电视剧`；留空不限 |
| 生效媒体分类 | 默认 `综艺`；留空不限 |
| 匹配完整路径 | 默认关（只匹配文件名） |
| 保留记录条数 | 详情页展示用，不影响过滤行为 |

> ⚠️ **已知边界**：关键词按**文件名**正则匹配，因此"发行组名/站点标记里恰好含某个关键词"会被误伤 —— 内置英文/数字默认词已统一做词边界处理（`MAXPLUS` / `StartUp` 实测不会被误伤），但**自己新增关键词时建议先对着自己的下载目录核一遍**（`find . -maxdepth 3 -type f -iname '*关键词*'` 这类粗筛即可）；另外本插件通过包装宿主整理计划入口实现，MoviePilot 大版本升级后请留意插件日志里的补丁状态（失配会自动禁用并告警，不会静默出错）。

## 豆瓣开分通知（DoubanScoreWatch）

跟踪订阅资源的豆瓣评分：订阅时豆瓣还没有分，出分后推送一条通知，包含评分、评价人数、首次观测日期与豆瓣链接。

| 项目 | 说明 |
| --- | --- |
| 标签 | 消息通知, 豆瓣 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/doubanscorewatch` |
| 外部依赖 | 无；复用 MoviePilot 内置豆瓣接口，可选填豆瓣 Cookie 兜底 |

### 功能特性

- **只追无分条目**：订阅时豆瓣已有分的只记入档案，不补发开分通知
- **开分判定**：评分大于 0 且评价人数达到门槛（默认 50 人），避免刚开分时个位数评分误报
- **按豆瓣条目追踪**：多季订阅共用一个豆瓣条目时只通知一次；豆瓣按季拆分时可给同一媒体绑定多个条目
- **季与集数对齐**：单季订阅优先按豆瓣标题的「第X季 / Season X」对齐；TMDB 一季而豆瓣拆成「第一季 / 年番1 / 年番2…」的长篇动画，按累计集数区间落位到当前集所在的条目
- **随机检查窗口**：默认每天 1 轮、落在 21:00–23:00 内随机时间，可配 1–4 轮；条目之间自动降速
- **可选继续追分**：开分后继续跟踪，分差达到阈值（默认 0.5）再提醒，最长 90 天
- **静默时段**：只推迟通知，不停止检查，通知不会丢
- **AI 季映射（默认关）**：仅对未匹配条目把候选交给 MoviePilot 已配置的大模型判断；返回结果强校验，可选高置信度自动绑定
- **手动兜底**：详情页可点选候选绑定、重匹配、忽略/恢复；设置里支持 `媒体来源:媒体ID=豆瓣ID` 形式的手动绑定
- **自定义豆瓣 Cookie**：匿名接口被风控时用 Cookie 抓网页兜底

### 使用说明

1. 安装后在设置页勾选「启用插件」并保存，默认每天 1 轮、21:00–23:00 内随机执行
2. 想立刻建档可点详情页「立即检查」，手动检查不占用当天定时轮次
3. 未匹配条目会在列表里列出豆瓣候选，点【绑定】即可；搜不到条目时用【重匹配】或在设置里手动填写
4. 豆瓣不提供「开分日期」，通知中的日期是插件首次观测到有效评分的日期

> 开分通知只发一次；需要持续跟踪评分变化请打开「开分后继续追评分变化」。

## TG 磁力离线（TgOfflineBot）

在 Telegram 里把磁力、ed2k 或种子链接发给 bot，直接提交到 115 网盘离线下载；下载完成后在整理前做预检，整理结束后按剧静默聚合入库通知（STRM 核对待开）。

| 项目 | 说明 |
| --- | --- |
| 标签 | 工具 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/tgofflinebot` |
| 外部依赖 | 需安装并启用 **P115StrmHelper**（提交离线、列举目录、触发整理）；AI 识别复用 MoviePilot 已配置的大模型（可选） |

### 功能特性

- **自带接收端**：插件内独立长轮询，不依赖宿主的 Telegram 通知渠道；停止时最多等一个轮询周期
- **批量提交**：多条链接按批提交（默认 20 条/批、批间隔 30 秒），提交前查离线任务列表，已存在的自动跳过
- **库已存在则拦截**：整理前查 Emby 媒体库，已入库的不再重复整理；剧集按集判断，可选择同时删除 115 上的源文件
- **整理前 MP / AI 比对**：把 MoviePilot 的识别结果与本机大模型的识别结果对比；不一致时暂停整理并推送「按 MP / 按 AI」按钮，超时按 MP 结果继续
- **选项下发到群**：选项消息发在群里时，任何群成员都能点按钮决定这一批的整理方式
- **完成通知**：115 网盘整理不产生 TransferComplete 事件，插件改为按整理历史巡检补发；同一部剧按「标题+季」静默聚合（默认 300 秒），整季顺序整理只发一条并列出集号，持续有新集最多压 30 分钟；聚合键含年份与媒体类型，同名不同年份的电影、电影与剧集版各自成条，不同季 / 不同剧交错入库互不串条；去重表持久化，插件重载不会重发旧通知
- **STRM 核对**：默认关闭；在配置页打开后整理完成会延时核对本地 STRM 是否生成，本地根目录与网盘根目录需自行配置映射，未配置时不做猜测
- **专属目标目录**：可指定提交落盘目录（默认取 P115StrmHelper 的离线下载目录 + 专属子目录，默认 `TG`）；目录不存在时提交前自动创建，被当空目录删掉后下次提交自动重建。目录内的任务按**路径前缀**判定来源，不再依赖任务名匹配
- **下载完成自动整理**：提交到指定目录的任务不会进入 P115StrmHelper 的整理队列，插件自行轮询离线任务，完成后主动触发整理；多文件任务整理其子目录，单文件任务仅在目标目录没有其它项目时整理根目录，避免把别的任务一起推进队列
- **异常任务清理**：0% 卡死、有进度长时间未完成、115 侧下载失败或重试中（默认 30 分钟）都会删除任务；一轮删除多个只发一条汇总通知，同一任务 30 分钟内不重复删除与通知
- **残留清理**：递归进入任务目录的子目录（含 `Featurettes`、`Promos` 这类花絮目录），按「只保留正片」判定——花絮、访谈、预告、样片、广告、字幕、图片等一律判删；清空后的空目录带重试队列，避免 115 列表延迟导致漏删。同时清掉 MoviePilot 里对应的失败历史与队列项；待整理目录里已没有本插件任务时会暂停定时巡检，等新提交、新入库记录或整理事件再恢复，离线任务尚未落盘时不会休眠，也可用「休眠后兜底复查间隔」（默认 0 = 不复查）定期兜底；这类后台维护动作只写日志，不推送通知

### 使用说明

1. 安装并启用 P115StrmHelper，确认其离线下载与目录浏览可用
2. 在 @BotFather 用 `/setprivacy` 把 bot 设为 **Disable**，否则 bot 收不到群里的链接消息
3. 在插件配置页填写 bot token、白名单（用户 ID / 群 ID / @用户名）与通知会话；目标目录留空即自动使用「P115StrmHelper 离线目录 + 专属子目录」，也可手填覆盖
4. 给 bot 发链接即可提交；支持 `/status`、`/dir`、`/allow`、`/deny` 等指令维护白名单与目标目录

> 白名单、群 ID、目录等一律在插件配置里填写，仓库不内置任何账号默认值。

- 工作流第一步是 **版本一致性校验**（`.github/scripts/verify_plugin_versions.py`），要求：
  1. `version.py` 中定义了 `VERSION`；
  2. 该 `VERSION` 与 `package.v2.json` / `package.v3.json` 里的 `version` **完全一致**；

- 以上任一条件不满足，工作流会在校验阶段直接失败，不会产出 Release —— 这是为了避免「清单版本已升、插件类属性仍是旧值」导致用户端**一直提示有更新**但装不上新版本。
- 改完代码后必须同步更新对应清单里的 `version`，否则发布工作流不会触发。

### 115网盘STRM助手（P115StrmHelper）

115 网盘 STRM 生成一条龙服务，覆盖 STRM 生成、302 跳转、转移整理、媒体库同步删除等完整链路。

| 项目 | 说明 |
| --- | --- |
| 标签 | 云盘 |
| 适用版本 | MoviePilot >= 3.0.0 |
| 源码目录 | `plugins.v3/p115strmhelper` |

> 归档前提示（历史）：上游 3.0.0 与本地 2.7.25 的插件 ID 同为 `P115StrmHelper`，本仓库已下架，不再存在同时订阅导致的覆盖问题。

#### 功能特性

- **STRM 生成**：全量 / 增量生成，支持多账号、多目录、媒体库分类
- **Rust 加速**：随插件分发 `full_strm_sync` / `txt_tree_storage` / `share_strm_scan` 的 cp312 与 cp314 轮子，`Python 3.12` 与 `3.14` 宿主都自动启用（大目录 / 大批量场景明显更快）；扩展缺失（如 3.13 宿主）时自动回落纯 Python 路径，功能一致
- **302 跳转服务**：Open / Cookie 两种模式，供 Emby / Jellyfin 直连播放；同键并发请求做**单飞合并**，仅向 115 请求一次，避免缓存雪崩
- **多端播放**（账号副本）：同一文件多端同时播放时自动创建副本，规避 115 单文件并发限制
- **转移整理**：接管 MoviePilot 整理流程，支持 115 内部移动/复制、命名识别、失败重试；已适配 V3 宿主的方法改名与作业队列归属，**补丁未生效时会明确报错并回退原生整理**（不再出现"日志说已启用、实际逐个整理"的静默失效）；未识别、缺集数、重复投递、非 115 回退等提前/失败路径均按宿主 durable 语义收口，**不会把同一文件反复重投**
- **媒体库同步删除**：媒体服务器删除媒体时联动清理网盘文件与 STRM，含目录安全防护
- **FUSE 挂载**：把 115 网盘挂载为本地目录，供扫描与播放
- **分享 STRM 清理**：扫描分享链接中的冗余文件，支持批量清理与缺失媒体检测
- **本地 STRM 备份**：本地生成 STRM，不依赖网盘
- **HDHive 资源获取**：从 HDHive 站点获取资源并入库
- **侧栏仪表盘**：STRM 同步记录、运行状态、同步删除历史、网盘整理、全量同步五个面板

#### 使用说明

1. 安装并启用插件后，在**配置页**填写 115 账号（扫码授权）与 STRM 生成目录
2. 按需开启 **302 跳转服务**，把地址填入 Emby / Jellyfin 的代理设置
3. 需要历史全量补档时点**全量同步**，日常新增走**增量同步**（自动触发）
4. 主界面左侧导航可进入**115助手仪表盘**查看运行状态

#### 注意事项

- 本插件为主版本 3.x，与上游 V2 版本（2.x）**数据不互通**，不建议在 V2 环境安装
- 在 **MoviePilot V2** 上因 `system_version` 要求 `>=3.0.0`，该插件不会出现在插件市场列表中——这是版本约束的正常表现，**不是发布故障**
- 插件数据库迁移锚点、事件队列名沿用上游命名，便于从上游 V2 迁移时保留既有数据
- **增量同步报 `'P115ClientWithTimeout' object is not iterable`**：这是 p115client 在 115 会话异常时抛出的**库内异常**，不是插件逻辑错误，重试也不会成功；插件会把这类异常转成带处置指向的提示，并跳过无意义的重试。**处理办法**：在插件配置里更新 115 Cookie（必要时在 MoviePilot 存储设置里**重新登录 115**），然后**重启 MoviePilot**；同类现象是 `115网盘储存（P115Disk）` 报 `'NoneType' object has no attribute 'model_dump'`——同为 115 调用失败
