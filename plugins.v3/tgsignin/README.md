# Telegram 自动签到（TgSignin）

MoviePilot V3 插件：多个 Telegram 账号按 cron 定时到各自订阅的 bot 签到。

## 功能

| # | 能力 | 说明 |
|---|---|---|
| 1 | 多账号 | 数量不限，一行一个（`标识 | 显示名 | 手机号`） |
| 2 | 多签到目标 | 每个账号可配多个目标：bot、公开群（`@用户名`）或私有群（数字 ID，`-100` 开头）；每个目标独立配置签到方式与等待秒数 |
| 3 | 两种签到方式 | **按钮式**：先发 `/start` 拉菜单，再点文字含「签到」的按钮；**命令式**：直接发命令（如 `/checkin`） |
| 4 | 两阶段登录 | 账号槽里选「发送验证码」保存 → 填验证码后选「确认登录」保存；兼容两步验证（2FA），全程在插件内完成 |
| 5 | 定时签到 | 执行周期用 MP 的 cron 选择器（点开可选每天/每周/每月与时间，也可手输五段式），默认 `0 9 * * *` |
| 6 | 手动签到 | 详情页「立即签到」按钮，或命令 `/tgsignin [账号] [bot]` |
| 7 | 结果展示 | 详情页表格：每个 bot 最近一次结果（时间/账号/bot/状态/回复摘要/AI 复核），另有账号登录状态表与 AI 归纳关键词表 |
| 8 | 通知可配 | 四档：不通知 / 仅失败时 / 仅成功时 / 成功与失败都通知（默认仅失败时） |
| 9 | 后台执行 | 发送验证码 / 确认登录 / 立即签到都立刻返回，前台不转圈；结果看详情页状态与通知 |
| 10 | 结果分档 | 每条结果按 bot 回复分为 `签到成功` / `今日已签到` / `未确认` / `失败`，通知与详情页都显示；取回复带归属判定（私聊按发送者精确匹配、群里排除真人发言），配了「回复归属标识」时还要求回复里出现它 |
| 11 | 关键词可配 | 三栏关键词（签到成功 / 已签到 / 签到失败）各自留空即用内置词表；回复命中失败词直接判失败 |
| 12 | AI 辅助判定 | 「自动使用 AI 确认」开启后，只对「未确认」结果调用 MP 内置智能助手复核；详情页「AI 复核」列区分 `AI 判定成功/已签到/失败` / `AI 无法判定` / `AI 异常` |
| 13 | AI 自动归纳关键词 | 「AI 自动归纳关键词」开启后与 AI 复核**复用同一次调用**，把回复里逐字摘取的短语写回对应关键词栏（**只增不删、写入前查重**），详情页留「AI 归纳关键词」表；默认关闭 |
| 14 | 失败重试 | 失败目标按「失败重试间隔（小时）」到期自动重试（默认 6 小时，填 `0` 关闭）；每小时检查一次到期项。账号整轮没跑成（连接超时 / 未登录 / 连接异常）时按该账号的每个启用目标各记一条失败，同样进重试窗口 |
| 15 | 并发签到上限 | 默认 `1`（串行）；`2-4` 时同一账号内每个 bot 一路同时触发，含错峰抖动与 FloodWait 退避重试 |
| 16 | 今日状态表 | 详情页按目标展示「今日状态 / 尝试次数 / 最后尝试 / 下次重试」，行内可**单独重试**该目标，也可点「测试」列出该 bot 当前真实按钮文案 |
| 17 | 退出登录 | 配置页每个账号槽的「退出登录」按钮带**原生确认弹窗**；点击只把该槽「登录动作」回填为「退出登录」，按保存后删除该账号 session 与登录记录（也可在「登录动作」下拉里直接选） |
| 18 | 首页仪表盘 | 插件仪表盘卡片显示「今日 x/y 个目标已完成 + 最近一次 + 失败目标」 |
| 19 | 按钮文字多候选 | 「按钮文字/命令」支持多候选（`签到|每日签到`），命中任一即可；都没命中时失败信息会列出实际看到的按钮 |
| 20 | 未确认单列 | 「未确认」既不算成功也不算失败：摘要与通知写成「x/y 成功，n 项未确认」，不再并进成功数 |
| 21 | 查群号 | 详情页每个账号一个「查询群组」按钮（只读拉取会话列表，不发任何消息），另有「更新群组（全部账号）」一次刷新所有账号；列出群名 / 群号 / 是否公开 / 类型 / 是否已配为目标；也可用命令 `/tggroups <账号标识>` 把列表发到聊天里；配置页每个目标槽都有「从已查到的群组选」组合框（可输入群名关键词筛选，**候选只列该行账号的群组**）+ 「填入本槽」按钮，在候选里点选即可一键写进该槽的「bot / 群」。群组列表**不自动更新**，只在这两处按钮或命令触发时刷新 |
| 22 | 槽位 ↔ 文本同步 | 配置页的槽位与文本模式自动保持一致（槽位模式把槽位镜像进文本、文本模式把前 4 个账号 / 前 8 条目标回填进槽位），不再出现「改了槽位、文本还是旧的」；文本里超出槽位容量的条目只留在文本里、UI 显示不了 |
| 23 | 目标栏按需显示 | 「bot 用户名 / 群」这一栏文案明确私聊 bot 与群都能填（公开群 `@群用户名`、私有群 `-100…` 数字 ID）；「回复归属标识」**只在该行是群目标时出现**（bot 私聊不显示），判断依据是本行目标的形态（数字 ID / 已查到的群 / 群用户名） |

## 使用步骤

1. **装插件**：插件市场安装后启用，保存一次配置。
2. **填账号**：账号区打开「账号 1」开关，填显示名与手机号（标识由槽位自动生成 `acc1…`，不用填）。
3. **填签到目标**：目标区打开某一行开关，选账号、在「bot 用户名 / 群」里填私聊 bot 或群、选方式（按钮式/命令式）、填按钮文字或命令；等待秒数默认 15（bot 回复慢可调大）。按钮文案不确定就先填「签到」，之后用详情页「测试」按钮看该 bot 实际按钮文字再改。要在**群里**签到就把「bot 用户名 / 群」填成群：公开群填 `@群用户名`，私有群填数字 ID（`-100…`，可先用右侧「从已查到的群组选」挑，该账号已加入该群即可）；群内签到一般用**命令式**，命令写 bot 在群里要的形式（如 `/checkin@example_bot`）。同一个群里多人同时签到、或群里闲聊较多时，把该目标的「回复归属标识」填上（自己的站点账号名等），这样只有回复里出现它才算本次结果——这一栏**只在本行是群目标时出现**（bot 私聊用不到）。
   - **不知道群号怎么办**：到插件详情页点该账号的「查询群组」（或发命令 `/tggroups acc1`），列表里的「群号」就是可以填进目标的数字 ID；私有群没有 `@用户名`，只能用这个数字 ID。查过一次之后，配置页每个目标槽的「从已查到的群组选」里就能挑：**候选只列该行账号的群组**，**输入群名关键词筛选**（如输入「交流」），在候选里点选后按「填入本槽」写进该行，再按「保存」生效。改了该行账号要先保存并重开配置页，候选才会换成新账号的群；换了新群、或加了新群之后，回详情页点「更新群组（全部账号）」刷新一次列表（列表不会自动更新）。
4. **登录**（每个账号一次，全程在插件内）：
   1) 在该账号槽把「登录动作」选成 **发送验证码** → **保存**（保存立刻返回，码在后台发）；
   2) 到该账号的 Telegram 看验证码；
   3) 把码填进该账号槽的「登录验证码」（开了两步验证再填「两步验证密码」），「登录动作」选成 **确认登录** → **保存**；
   4) 回到详情页看状态栏「最近登录动作」是否成功（失败会发通知）。
   5) **要退出登录**：在该账号槽点「退出登录」按钮 → 弹窗确认 → 按「保存」，即删除该账号 session 与登录记录（不必重走登录流程）。
   也可以直接在聊天里：`/tglogin acc1 12345 [两步密码]`。
5. **验证**：详情页点「立即签到」（后台执行），或用命令 `/tgsignin` / `/tgstatus` 看结果。
6. **可选增强**：详情页/配置里的「并发签到上限」「自动使用 AI 确认」「AI 自动归纳关键词」默认都是关的；想用先开一个跑一轮看结果，再决定是否全开（AI 两项会用 MP 内置智能助手，签名结果未确认时才调用）。

## 配置格式

| 字段 | 说明 |
|---|---|
| 账号槽（最多 4） | 开关 + 显示名 + 手机号 + 登录动作 + 登录验证码 + 两步验证密码；标识自动 = `acc1…acc4`（用作 session 文件名） |
| 签到目标槽（最多 8） | 开关 + 账号（下拉选）+ bot 用户名 / 群 + 方式（下拉：按钮式/命令式）+ 按钮文字或命令 + 等待秒数 + 回复归属标识（**仅群目标行显示**，可选） |
| 从已查到的群组选 + 填入本槽 | 每个目标槽一组：组合框里是最近一次查询到的、**该行账号的**群组（`群名（群号）`），**可直接输入群名关键词筛选**（群多时按名字缩范围，也可输入群号数字）；在候选里点选后按「填入本槽」即把群号 / `@用户名` 写进同一行的「bot / 群」字段，按「保存」生效。填入时会**自动解析出群标识**（选中整项取 `value`；框里是 `群名（群号）` 完整标题串则从 `（群号）` 里截出群号），不必手动删掉群名。候选随行的账号走：本行没选账号、或该账号还没查过群号时框是空的（去详情页点「查询群组」或「更新群组」）；改了本行账号要走一次「保存 + 重开配置页」候选才换。**只在框里打了半截筛选词、认不出群标识时才会弹提示**，避免把无效值写进目标 |
| 高级：文本模式 | 打开后用两个多行文本域配置（`标识 \| 显示名 \| 手机号`、`账号标识 \| 目标 \| 按钮或命令 \| 内容 [\| 等待秒数] [\| 回复归属标识]`），适合批量粘贴、条目数不限；与槽位**自动同步**：槽位模式把槽位镜像进文本，文本模式把前 4 个账号 / 前 8 条目标回填进槽位。超出槽位容量的条目只留在文本里（UI 显示不了），保留不会被清掉 |
| 目标可填什么 | `@用户名`（bot / 公开群）；私有群或频道填数字 ID（`-100…`，如 `-1001234567890`）。邀请链接（`t.me/+xxx`）不支持，填了会在配置问题里提示，且不会回显链接本身 |
| 回复归属标识（群签到可选） | **只在群目标行显示**（该行目标填了 `-100…` 数字 ID、或从「从已查到的群组选」里挑过群组、或填了查得到的群用户名时出现；bot 私聊不显示）。填了之后，只有回复里出现它才算本目标的本次结果；用于同一个群里多人同时签到、或群里另有闲聊时区分「这条回复是不是回给自己的」。留空时群里只排除真人发言（同一个 bot 回给别人的结果仍可能被误认，所以群目标建议填上） |
| cron | 五段式 | 默认 `0 9 * * *` |
| 代理 | 模式（跟随 MoviePilot / 自定义 / 直连） | 默认跟随 MP 的 `PROXY_HOST`；自定义时才需填类型/主机/端口 |
| 执行周期 | cron 选择器 | 点开可选「每天/每周/每月 + 时间」，也可直接手输五段式 cron |
| 通知方式 | 四档 | 不通知 / 仅失败时（默认）/ 仅成功时（需全部成功）/ 成功与失败都通知 |
| 失败重试间隔 | 小时，默认 `6` | 失败目标到期自动重试；填 `0` = 关闭重试 |
| 签到成功 / 已签到 / 签到失败关键词 | 每栏一组关键词 | 逗号或换行分隔；留空用内置词表；命中失败词即判失败并进入失败重试 |
| 自动使用 AI 确认 | 开关，默认关 | 只对「未确认」结果调用 MP 内置智能助手复核；判定成功算成功、判定失败进重试、无法判定保持未确认 |
| AI 自动归纳关键词 | 开关，默认关 | 与上一项复用同一次 AI 调用，把回复里逐字摘取的词写回关键词栏（只增不删、写入前查重） |
| 并发签到上限 | `1-4`，默认 `1` | `2` 起同一账号内每个 bot 一路并发（错峰抖动 + FloodWait 退避重试） |
| api_id / api_hash | 应用级凭据 | 默认用 Telegram Desktop 公开值（可登录任意多账号），可整套替换 |

### 通知文案

失败（示例：2/5 成功）：

```
【Telegram 自动签到】
2/5 成功，3 项失败（2026-10-06 09:00:03 · 定时）

失败明细：
- 账号1(acc1) → @example_bot_a：最近 5 条消息里没找到含「签到」的按钮
- 账号2(acc2) → @example_bot_a：账号 acc2 未登录或 session 已失效，请重新登录
```

成功（示例：5/5 全绿，其中 1 项为重复签到）：

```
【Telegram 自动签到】
5/5 全部成功（其中 1 项为今日已签到）（2026-10-06 09:00:03 · 定时）

- 账号1(acc1) → @example_bot_b：签到成功｜🎉 签到成功 | 10 子弹 💴 当前持有 | 5 子弹 ⏳ 签到日期 | 2026-10-06
- 账号1(acc1) → @example_bot_c：今日已签到（bot 弹窗：您今天已经签到过了）
- 账号1(acc1) → @example_bot_d：今日已签到｜✅ 今日已签到，明天再来。
- 账号2(acc2) → @example_bot_a：今日已签到（按钮式：已点击，bot 未返回签到结果）
```

> 每行摘要截 60 字；明细最多列 10 条，超出显示「…等 N 项」。登录动作失败始终通知。

**结果分档口径**：

| 分类 | 判据 | 通知里的写法 |
|---|---|---|
| 签到成功 | 回复或弹窗含「签到成功」 | `签到成功｜<bot 回复摘要>` |
| 今日已签到 | 弹窗含「已签到」 | `今日已签到（bot 弹窗：<弹窗文本>）` |
| 今日已签到 | 回复里含「已签到」 | `今日已签到｜<bot 回复>` |
| 今日已签到 | 按钮式点击后只回菜单 | `今日已签到（按钮式：已点击，bot 未返回签到结果）` |
| 未确认 | 命令式回复里没有成功标记 | `未确认（未在回复里看到签到结果）` |
| 失败 | 无回复 / 执行异常 | 失败原因 |

> 弹窗文本来自 Telegram 的 callback 应答（bot 用 ``answerCallbackQuery`` 弹的那句话），
> 这是区分「emby 类 bot 重复签到」最直接的证据。

> 取回复只认三条都满足的消息（读的是该会话最近几条）：① 本次发送之后的；
> ② 归属判定通过（私聊：发送者就是目标本身；群里：排除真人发言，
> 同一个 bot 回给别人的结果靠「回复归属标识」区分）；③ 配了「回复归属标识」时
> 回复里必须出现它。都不满足就不拿别人的消息顶账，判「失败」并按「失败重试间隔」重试。

**AI 复核列的含义**（仅在「自动使用 AI 确认」或「AI 自动归纳关键词」开启时才有内容）：

| 显示 | 含义 |
|---|---|
| `AI 判定成功` / `AI 判定已签到` / `AI 判定失败` | AI 给出结论（已签到同样算成功，不会误报为签到成功） |
| `AI 无法判定` | AI 没给出可用结论，结果保持「未确认」 |
| `AI 异常：<原因>` | 调用过程出错（原文截断保存，便于回查） |

> 说明：MoviePilot 的 JSON 配置表单没有按钮组件，做不出「增删行」的列表控件，所以账号与目标用多行文本表达 —— 增删就是加减一行。

## 命令

| 命令 | 作用 |
|---|---|
| `/tgsignin [账号标识] [bot]` | 立即签到；不带参数即全量 |
| `/tglogin <账号标识> <验证码> [两步密码]` | 在聊天里完成登录（会先自动发码） |
| `/tgstatus` | 查看账号/目标数量与最近 10 条结果 |
| `/tggroups [账号标识]` | 查群号：只读列出该账号的群 / 频道与数字 ID（不发任何消息）；不带参数用第一个账号 |

## 排障

| 现象 | 处理 |
|---|---|
| 「连接失败」 | 详情页点「连通性自检」；确认代理主机/端口可达，且代理侧 Telegram 分流规则生效 |
| 「未登录或 session 已失效」 | 重新走一遍两阶段登录（或 `/tglogin`） |
| 「没找到含「签到」的按钮」 | 该 bot 的菜单按钮文字可能不同（如「每日签到」），把按钮文字改成实际文字即可 |
| 「没找到含「签到」的按钮」但不知该填什么 | 详情页「今日签到状态」表该行点 **测试**：会跑一次 /start 并列出该 bot 实际按钮文案，照抄进配置即可。也可写成多候选：`签到|每日签到` |
| 「发送后没等到 bot 回复」 | 把该目标的等待秒数调大（命令式默认 15 秒）；群里签到还要留意：回复必须是**目标自己发的**、且（若配了「回复归属标识」）回复里要出现该标识 |
| 该账号启用了两步验证 | 登录时填「两步验证密码」；登录成功后建议清空 |
| 点了按钮没有前台提示 | 发送验证码/确认登录/立即签到都是后台执行：结果看详情页状态栏，失败会发通知 |
| 「验证码为空」 | 先把验证码填进该账号槽的「登录验证码」并保存，再选「确认登录」保存 |
| 详情页显示「数据加载失败」（点重试也没用） | 详情页渲染异常，不是网络问题：查 MP 日志有无 `插件 TgSignin 调用方法 get_page 出错`。旧版在「AI 归纳关键词」第一次有记录后必现，升级到含该修复的版本即可恢复 |
| 结果一直是「未确认」 | 该 bot 的回复里没有成功/已签到关键词：先看回复摘要，再把实际说法加进「签到成功关键词」；或打开「自动使用 AI 确认」让 AI 判。群里签到还可能是没取到自己那条回复（别人同时签到/闲聊），把该目标的「回复归属标识」填上 |
| 私有群填数字 ID 后报「找不到目标」 | 数字 ID 靠该账号的会话缓存解析：插件会先自动补拉一次会话列表再试；仍失败说明这个账号不在该群里、或该会话从未在这个账号出现过——先用该账号手动打开一次该群，或改用公开群的 `@用户名` |
| 目标填成 `t.me/+xxx` 邀请链接 | 不支持。私有群填数字 ID（`-100…`），公开群或 bot 填 `@用户名`；配置问题里会提示，且不会回显链接本身 |
| 同一个群里多人同时签到时结果不稳 | 正常现象：群消息是共享的。把该目标的「回复归属标识」填上（站点账号名等），只有回复里出现它才算本次结果；也可以把等待秒数调大，让 bot 的回复先落地 |
| 群里签到会公开发言 | 正常：群内签到就是让该账号在群里发一条命令（如 `/checkin@example_bot`），群成员都能看到，bot 的结果也发在群里。不接受公开就在这类目标上关掉自动签到 |
| AI 复核显示「无法判定」/「异常」 | 「无法判定」= 模型没给结论（下次可重试）；「异常」= 调用失败（看通知/日志里的原因，通常是模型或网络）；两者都不影响签到本身 |
| 失败后没有自动重试 | 确认「失败重试间隔（小时）」不为 `0`；只有判为失败的目标才进重试队列，每小时检查一次到期项 |
| 点「立即签到」没反应/重复点了几次 | 同名任务互斥：已在跑时会提示「已有签到任务在运行」，不会叠成多份并发；等这一轮结束再看详情页 |
| 结果表「AI 复核」列空白 | 正常：只有开启「自动使用 AI 确认」或「AI 自动归纳关键词」后才会有内容 |
| 「查询群组」查不到群 / 列表是空的 | 只列**群与频道**，私聊不计；确认用的是加入了这些群的账号。查询本身只读（发 `GetDialogs`），不发消息，所以不会打扰群里 |
| 群列表多久更新一次？ | 不自动更新：只有点详情页的「查询群组 · <账号>」/「更新群组（全部账号）」，或发 `/tggroups <账号>` 时才刷新。新加了群就点一次「更新群组（全部账号）」 |
| 配置页「从已查到的群组选」里没有我刚加的群 | 候选来自最近一次查询缓存，先回详情页点「更新群组（全部账号）」刷新；刷新后重进配置页即可看到 |
| 配置页「从已查到的群组选」是空的 | 两种情况：① 该行**还没选账号**（候选只列本行账号的群）；② 该账号还没查过群号——先确认本行账号并保存，再到详情页点「查询群组」/「更新群组」；也可以发 `/tggroups <账号>`（会顺带写缓存） |
| 换了本行的账号，候选还是旧账号的群 | 候选按「保存时的账号」生成：保存一次并重开配置页，候选就会换成新账号的群 |
| 看不到「回复归属标识」这一栏 | 该栏只在本行是**群目标**时显示：把目标填成群（`-100…` 数字 ID，或用右侧「从已查到的群组选」挑一个群）并保存后即出现；bot 私聊用不到这一栏 |
| 点选群组后按「填入本槽」仍提示认不出群标识 | 说明框里只是**输入中的筛选文字**、没有真正点选候选项——点选后框内会变成 `群名（群号）`，此时填入会自动截出群号。在候选列表里点一下再填入即可；急用时也可以直接在「bot / 群」里手填 `@用户名` 或 `-100…` 群号 |
| 点了「填入本槽」没生效 | 它只把群号写进该行的「bot / 群」字段，**仍需按「保存」**才会真正应用；另外要先在候选里选中一个群组（没选会弹提示） |
| 文本里写的条目比槽位多 | 正常：文本模式条目数不限，槽位最多 4 个账号 / 8 条目标。超出槽位容量的行只留在文本里（UI 显示不了），不会被清掉；槽位模式下生效的仍只有槽位里那些 |
| 改完槽位后文本还是旧的 | 不该出现：两种表达会自动同步（保存/加载时对齐）。若确实不一致，看 MP 日志有无 `插件 TgSignin` 的配置写入报错 |
| 日志里手机号是 `+1******0101` 这样的形式 | 正常：日志与 `state.json` 里的手机号一律打码；验证码 / 两步验证密码在登录成功后自动清空 |

## 目录结构

```
plugins.v3/tgsignin/
├── __init__.py            # 插件入口：配置表单、详情页、API、命令、定时服务
├── version.py             # 版本号唯一来源
├── requirements.txt       # telethon / python-socks[asyncio]
├── tgsignin.png           # 插件图标
├── core/
│   ├── config.py          # 账号/目标解析与校验、槽位 ↔ 文本同步
│   ├── groups.py          # 查群号：只读列出群/频道与数字 ID
│   ├── session.py         # 客户端构建、session 管理、连通性自检
│   ├── login.py           # 两阶段登录（含两步验证）
│   ├── signin.py          # 签到执行（按钮式 / 命令式）
│   ├── ai.py              # AI 复核（判定成功/失败/已签到）
│   ├── autofill.py        # AI 归纳关键词的合并与查重
│   ├── retry.py           # 失败重试到期判定
│   └── store.py           # 运行结果与登录状态持久化
└── tests/                 # 单元测试 + 变异测试
```

## 运行时数据

都在 `/config/plugins/TgSignin/` 下（容器重建不丢）：

| 文件 | 内容 |
|---|---|
| `sessions/acc_<标识>.session` | Telegram 登录态（含授权密钥，勿外传） |
| `login_pending.json` | 两阶段登录的临时状态（phone_code_hash） |
| `state.json` | 最近一次运行、账号登录信息、最近结果、AI 复核结论与 AI 归纳关键词记录、最近一次查群号的结果（供配置页下拉使用） |
